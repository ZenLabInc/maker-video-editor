# YouTube連携設計（実投稿は未実装）

初版の `upload-manifest` は動画のSHA-256、バイト数、絶対パス、タイトル、説明、非公開のメタデータを保存します。動画は送信しません。秘密情報も取得・保存しません。これは後続アップローダーへの入力契約であり、認証・投稿・再開を実装済みとは扱いません。

## 後続実装の状態管理

`prepared → session_created → uploading → uploaded → processing → complete` を永続化します。エラー時はretryableまたはneeds_reviewへ移します。動画ハッシュと投稿先チャンネルIDで排他ロックを取り、同じ動画の完了記録があれば再投稿を拒否します。セッションURL、サーバー確認済みバイト位置、動画ID、メタデータハッシュをトランザクションで保存します。セッションURLも機密扱いにしてGitに含めません。

再開可能アップロードを開始し、チャンクをPUTします。中断後はサーバーの受信済み位置を問い合わせてから送信を再開し、ローカル推測で先へ進めません。429／5xxには上限付き指数バックオフとジッターを使います。期限切れセッションや最終応答が不明の場合は自動で新規投稿せず、投稿履歴との照合・ユーザー確認を要求します。YouTubeの一般的な冪等キーがあると仮定せず、重複防止をローカル台帳と不確定状態の停止で実現します。

## 認証と明示実行

将来の `upload --execute manifest.json` のみがネットワークを伴う入口です。Desktop OAuthのブラウザー同意とループバックリダイレクトを使用し、最小のyoutube.uploadスコープを要求します。ユーザーはGoogle Cloudで自身のOAuthクライアントを用意します。クライアント設定やトークンを会話へ貼り付ける必要はありません。トークン保管はOSキーチェーンを優先し、JSONやログへ出しません。今回その認証フローは実行していません。

既定の公開設定はprivateです。対象チャンネル、子ども向け指定などの必須方針、タイトル、説明、公開範囲を確定してから送信します。投稿完了とYouTube側の処理完了は区別します。投稿後の処理失敗も状態へ反映します。

2020年7月28日以降に作成された未監査APIプロジェクトからの投稿は非公開に制限され、解除には監査が必要です。公開指定だけで解除できる設計にはしません。
